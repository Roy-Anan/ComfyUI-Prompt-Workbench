# 项目介绍：ComfyUI Prompt Workbench

## 1. 项目定位

ComfyUI Prompt Workbench 是一个专门使用本地 LLM 为本地 ComfyUI
工作流编写、优化、审核和管理图像生成提示词的本机浏览器 Web 工作台（免安装，见 ADR-0002）。

它不是 ComfyUI 的替代品，也不是通用工作流编辑器。ComfyUI
继续负责模型加载、采样、图像生成和原图保存；工作台负责工作流识别、模型提示词规则、Prompt
创作与安全写入、LLM/显存协调、任务队列、生成记录和 LoRA 资料管理。

## 2. 核心使用流程

1.  用户在工作台导入并选择一个 ComfyUI 工作流。
2.  工作台解析工作流，识别工作流类型、Checkpoint、架构、文本编码器、实际启用的
    LoRA，以及正向/负向 Prompt 节点。
3.  程序根据模型身份和本地规则库建立本次创作的精简规则集；不确定的识别结果交由用户确认。
4.  用户选择自然语言创作、原始 Prompt 优化或多轮对话创作模式。
5.  本地 LLM
    生成候选版本。候选先经过格式、术语、结构和规则检查，再供用户比较与编辑。
6.  用户审核最终英文 Prompt、中文辅助翻译、正负向内容和区块结构。
7.  用户明确确认后，程序只把白名单中的 Prompt
    字段写入工作副本/任务数据，并做写入前后完整性验证。
8.  入队前卸载本地
    LLM，验证模型已卸载且显存已释放到安全状态；失败或无法确认时禁止提交。
9.  工作台通过 ComfyUI HTTP API 提交任务，通过 WebSocket
    与状态接口跟踪执行；ComfyUI 负责实际生成和保存图片。
10. 任务完成后自动记录图片路径、缩略图索引、Prompt、工作流和模型快照、任务状态等历史信息。

## 3. 产品范围

### 第一阶段核心能力

-   本机启停脚本与本地服务生命周期管理（浏览器同源访问 127.0.0.1:17890）。
-   ComfyUI 连接配置、连通性检测和重连。
-   工作流导入、解析、身份识别与用户确认。
-   Prompt 节点白名单、写入差异检查和回滚保护。
-   架构/模型/Checkpoint 三级规则继承与组合。
-   本地 LLM 发现、选择、调用、输出校验与卸载验证。
-   Prompt 候选、正负向编辑、中文辅助翻译、区块编辑、术语保护。
-   用户主动保存的多草稿与版本历史。
-   出图队列、WebSocket 进度、异常恢复和生成历史。
-   SQLite 数据库、备份恢复、诊断报告。

### 后续扩展能力

-   LoRA 角色卡、标签/分组、封面与多张示例图。
-   LoRA 元数据提取、作者资料导入、触发词建议和常用组合。
-   LoRA 与工作流、Prompt、生成历史的关联展示。
-   Prompt 预设、区块预设、完整模板。
-   完整 UI 视觉打磨与体验优化。

### 明确不做或暂不做

-   不替代 ComfyUI 的图像生成引擎。
-   第一版不自动联网研究模型资料。
-   不接云端 AI API，不要求用户配置云端 API Key。
-   不自动下载或安装本地 LLM。
-   不自动启动、关闭或重启 ComfyUI。
-   不修改工作流中 Prompt 以外的字段。
-   不把模型、图片原件复制进工作台数据目录。
-   不做复杂模型关系可视化、LoRA
    排行榜、复杂统计、复杂容量管理或微服务拆分。

## 4. 工作流安全边界

这是整个项目最高优先级的约束。

### 允许修改

仅允许修改用户确认过的白名单字段，例如： - 已识别并确认的正向 Prompt
文本字段。 - 已识别并确认的负向 Prompt 文本字段。

具体节点
ID、字段路径和正负向角色必须绑定到当前工作流版本。工作流发生变化后，旧白名单立即失效，必须重新解析和验证。

### 绝对禁止修改

-   Checkpoint、VAE、文本编码器及其他模型选择。
-   LoRA 节点、LoRA 权重、启用状态。
-   KSampler 的 Seed、Steps、CFG、Sampler、Scheduler、Denoise 等参数。
-   图像宽高、Batch Size、Latent 参数。
-   节点类型、数量、ID、连接关系、输入输出结构。
-   任何其他不在 Prompt 白名单中的字段。

### 写入保护流程

-   导入时保留原始工作流文件，不覆盖。
-   在独立工作副本或任务快照上工作。
-   写入前保存原始快照并生成结构化差异。
-   差异只能命中白名单字段；任何额外变化立即拒绝。
-   写入后重新解析并校验 Prompt 内容和非白名单字段不变。
-   写入失败时停止流程并尽可能回滚；回滚状态不确定时禁止出图。
-   入队时冻结工作流、Prompt
    和模型参数快照；之后编辑草稿不得改变已入队任务。

## 5. 模型知识库

知识库分三级继承：

1.  架构级：例如 SD 1.5、SDXL、FLUX。
2.  具体模型级：例如 FLUX.1-dev、FLUX.1-schnell。
3.  Checkpoint 级：作者基于某架构训练的专属模型。

低层继承高层规则，可以补充或覆盖，但覆盖关系必须明确。规则区分强制要求、推荐写法和可选触发词。

模型资料采用人工云端研究、人工审核导入的方式： -
工作台生成统一研究任务书。 - 用户将任务书交给 ChatGPT、Gemini、Claude
等云端模型研究官方/作者/可靠资料。 -
云端模型按结构化格式返回资料、来源、版本、时间和证据。 -
用户审核差异后导入本地知识库。 - 本地 LLM
只使用已导入的规则，不负责联网研究、身份判断或复杂冲突裁决。

资料可信度标记：官方确认、可靠参考、社区经验、尚未验证。来源冲突保留冲突，不擅自下结论。

## 6. 模型身份与文件

-   模型身份记录与提示词规则分离。
-   SHA256
    是内容身份的最终依据；文件名、大小和修改时间只能作为变化检测线索。
-   相同 SHA256 的多个文件路径指向同一个模型身份，不重复建立身份记录。
-   完整 SHA256
    仅在首次登记、用户要求重新验证或元数据提示文件变化时计算。
-   官方哈希可优先使用；任何云端研究结果不得编造哈希。
-   轻量识别不扫描整块硬盘、不加载 GPU 模型。
-   用户登记模型目录后，只扫描指定目录。

## 7. Prompt 创作体验

支持三种模式： - 自然语言意图生成。 - 原始 Prompt
优化、扩写、精简和改写。 - 多轮对话式创作。

支持正向/负向 Prompt
同时生成或单独生成；默认每次生成一个候选；可指定区块重生成；提供轻微调整、适度优化、重新创作三种幅度，以及严格遵循、合理补充、自由发挥三种自由度。

Prompt 编辑采用结构化区块与完整文本双视图。英文是提交 ComfyUI
的实际内容，中文为辅助理解和编辑。中英文转换结果必须审核，不做机械一一映射。无法准确拆分的特殊语法必须原样保留。

支持锁定片段、术语保护、候选差异比较、撤销/重做、语法检查、Token
长度提醒、复制与 TXT/JSON 导入导出。

## 8. 草稿与生成历史

### 草稿

-   多份独立草稿；每个工作流有独立草稿箱。
-   每份草稿保存 Prompt、意图、对话上下文、锁定片段和模型环境快照。
-   只有用户主动点击保存才持久化；绝不自动保存。
-   切换草稿、切换工作流或正常关闭时，如有未保存修改，提示保存/不保存/返回。
-   异常退出不保证恢复未保存内容。
-   保存时记录重要版本；支持比较、备注和恢复。恢复产生新当前版本，不销毁旧版本。
-   草稿可收藏、打标签、搜索和关联生成结果。
-   删除有二次确认和回收站；永久删除草稿不删除生成历史和图片。

### 生成历史

每个任务自动保存能获取的信息： - 图片缩略图和原图路径。 -
工作流名称/标识。 - 当次正向和负向 Prompt 快照。 -
Checkpoint、LoRA、权重等模型信息。 - 生成时间。 - ComfyUI Prompt
ID、状态、开始/完成时间、输出文件名、错误信息等任务数据。

ComfyUI
仍保存原图；工作台只记录路径和缩略图索引，不复制或搬动原图。图片丢失时保留历史并标记文件不存在。

历史支持时间轴和图库双视图、按日期/工作流/Checkpoint/LoRA/关键词/状态筛选、导出记录和从历史反向创建新草稿。

## 9. LLM、显存与队列

-   第一版通过适配层连接用户已安装的 Ollama。
-   自动读取可用模型；用户选择默认创作模型；不自动下载/安装。
-   LLM 单任务执行；生成时可实时预览；可停止；失败不覆盖当前 Prompt。
-   不可用时不自动调用云端或切换模型。
-   出图前必须卸载当前 LLM
    模型，确认运行时不再报告模型驻留并确认显存释放；失败、超时或不确定都禁止提交。
-   队列先进先出，允许调整尚未执行任务；正在执行任务不可移动。
-   队列有待执行任务时不提前恢复 LLM。
-   ComfyUI 生成期间禁用 LLM 对话；任务结束/失败/终止后按设置恢复。
-   支持暂停、继续、取消待执行任务、明确中断当前生成、手动重试失败任务。
-   重试保留原始 Prompt、工作流和模型参数，不自动修改。
-   WebSocket 断线自动重连并通过 HTTP
    状态校准；未知结果不推断成功/失败。
-   工作台异常退出后恢复历史，未完成任务标记异常中断，不自动重出。

## 10. LoRA 资料库

每个 LoRA
有独立角色卡和详情页，包含封面/示例图、名称、作者、版本、文件名、兼容架构、类型、触发词、推荐权重、作者说明、来源、SHA256、路径、使用信息和个人反馈。

资料来自文件元数据、用户导入的研究结果和手动编辑；手动编辑优先，不被自动更新覆盖。支持多标签、自定义分组、搜索、常用组合和资料完整度提示。

工作流联动只读展示实际启用的 LoRA；强度为 0 或未启用的 LoRA
不作为生效模型。触发词采取智能建议+手动添加，绝不自动改工作流节点或权重。

## 11. 隐私、资源和运行环境

-   默认所有 Prompt、草稿、历史、模型资料和设置保存在本地。
-   不自动上传任何用户内容。
-   工作台数据目录可配置；模型和原图继续由用户原有目录管理。
-   只扫描用户登记的模型目录。
-   16GB RAM / 8GB VRAM 环境下采用按需检索规则，不把整个知识库塞给 LLM。
-   诊断报告由用户主动生成，默认不上传。
-   日志记录必要运行信息和错误，不记录不必要的敏感 Prompt 内容。

## 12. 成功标准

项目成功不是"能打开一个漂亮窗口"，而是： - 能可靠识别工作流和 Prompt
字段。 - 能证明 Prompt 写入没有改变其他工作流内容。 - 能在本地 LLM
显存释放验证通过后安全提交任务。 - 能恢复和追溯每次生成所用的
Prompt、工作流与模型快照。 -
能让新智能体只通过仓库文档就理解边界、定位模块并安全接手。
