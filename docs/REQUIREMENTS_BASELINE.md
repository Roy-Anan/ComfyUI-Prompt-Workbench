# 已确认需求基线（决策 01---132）

本文件记录用户已确认的产品需求。后续实现不得自行删减或改变这些约定。若技术实现存在冲突，先记录差异、说明影响，再由用户确认调整。

## A. 工作流识别与模型适配

-   导入 JSON 工作流后自动解析；识别
    Checkpoint、模型架构、文本编码器、正向/负向 Prompt 节点、实际启用
    LoRA 和相关辅助模型。
-   识别不确定时要求用户确认，不盲目猜测；用户可手动覆盖识别结果。
-   用户确认的识别结果可按工作流保存；工作流发生变化时必须重新解析和验证，旧白名单不可沿用。
-   模型身份库与提示词规则库分离。模型身份包含稳定
    model_id、文件名、SHA256、架构、版本和路径引用；规则通过 model_id
    关联。
-   同 SHA256
    文件视为同一内容身份，可有多个路径；移动/更名后通过身份重新关联；所有副本不可用时标记暂不可用，角色卡和历史仍保留。
-   SHA256
    是内容身份依据。文件大小、修改时间等只作为重新验证线索，不作为内容未变化的证明。下载登记时完整计算一次；之后按需重验。
-   官方哈希优先；研究资料不能编造哈希。轻量识别不加载模型、不使用
    GPU、不扫描整个磁盘。
-   用户登记多个模型目录，只扫描这些目录；支持首次登记、启动轻量检查、手动刷新和按需深度验证。
-   未知模型明确标记未知并展示依据，允许手动登记；不套用未经确认的规则。
-   支持 UI workflow 和 API workflow。UI workflow 与提交用 API prompt
    的转换必须可靠；无法解析或转换时提示用户，不做危险猜测。
-   自定义节点尽量解析；未知节点和字段保持原样。Prompt
    节点不确定时由用户指定。
-   默认不覆盖原始工作流文件，使用独立工作副本；导出或覆盖操作必须明确确认并完整检查。
-   检测 ComfyUI 中工作流外部变化；变化后重新解析验证。
-   读取 ComfyUI 版本并检查接口/节点兼容性；不兼容时提示。

## B. 工作流修改白名单与安全验证

-   仅允许修改当前工作流中用户确认的正向和负向 Prompt 文本字段。
-   任何非白名单字段变化均拒绝提交，包括节点类型/数量/ID、连接关系、Checkpoint、LoRA
    节点与权重、Seed、Steps、CFG、Sampler、Scheduler、尺寸、Batch
    Size、其他模型和参数。
-   写入前保存原始快照并显示正负向原文/新文及节点字段。
-   写入前对结构化数据做差异比较，差异必须全部落在白名单内。
-   用户确认后才写入；写入后程序自动验证 Prompt 正确、其他字段未变化。
-   写入失败时停止并尽可能回滚；回滚不确定禁止出图。
-   特殊语法检查包括括号匹配、语法支持情况、必要触发词等；明确错误阻止写入，普通警告可忽略，未知只提醒。
-   未知语法不得擅自修复或改写。

## C. 模型知识库与研究资料

-   知识库三级继承：架构级 → 具体模型级 → Checkpoint
    级。低层可补充或覆盖高层，优先级由程序明确管理。
-   规则区分强制要求、推荐写法、可选触发词；规则包含来源、版本、更新时间和可信度。
-   多模型组合由程序识别、合并、处理优先级和冲突；本地 LLM
    只接收精简后的最终规则，不自行决定复杂优先级。
-   实际启用 LoRA 才参与规则合并；未启用或强度为 0 的 LoRA
    不作为生效模型。
-   资料来源采用手动云端研究模式：工作台生成统一任务书，用户交给云端大模型研究官方/作者/可靠来源，按结构化格式返回，用户审核后导入。
-   第一版不接云端 AI API，不处理 API Key 或云端调用费用；本地 LLM
    不联网研究。
-   统一研究模板覆盖架构、Checkpoint、LoRA、文本编码器和辅助模型。
-   导入前检查结构、来源、身份关联和冲突，展示差异，用户确认才导入。
-   资料可信度：官方确认、可靠参考、社区经验、尚未验证。来源冲突保留证据与冲突，不擅自裁决；社区经验不能自动升为强制规则。
-   支持重新生成研究任务书、版本差异预览、更新审核、历史版本与回退。
-   模型关系只在程序内部维护，不做用户可见的复杂关系图。云端研究可辅助确认关系，未知关系保持未知。
-   按当前工作流动态检索相关规则，不把全知识库塞入 LLM 上下文。

## D. Prompt 创作模式与输出

-   三种模式：自然语言意图生成、原始 Prompt 优化、对话式创作。
-   同一模型适配引擎服务三种模式。
-   生成结果先成为候选，审核后才应用；默认每次生成一个候选，可再次生成。
-   支持同时生成正负向、只生成正向或只生成负向；未生成的一侧保持原样。
-   支持锁定片段；后续优化尽量保留锁定内容。
-   支持轻微调整、适度优化、重新创作；创作自由度为严格遵循、合理补充、自由发挥，默认合理补充。
-   核心意图和锁定内容不得因自由发挥被擅自改变。
-   关键信息缺失影响画面时只问最关键的一问；非关键内容按自由度处理；用户选择自由发挥后不反复追问。
-   支持指定一个或多个区块重新生成；未选区块保持，锁定区块默认不动；依赖关系只提示，不自动添加。
-   默认候选可比较、接受、放弃、手动删除；不做复杂容量管理。
-   LLM 实时输出预览；未完成内容仅为临时输出；格式验证通过后才成为候选。
-   支持停止生成；未完成输出无效，不覆盖当前 Prompt，不影响其他候选。
-   LLM 单任务执行；失败不自动重试，不自动切换云端模型。
-   输出结构必须验证区块、正负向和中英文对应；失败保留原始输出并说明，未验证内容不可写入工作流。
-   失败诊断展示任务阶段、原因、可能关联加载/显存/连接/格式问题、处理建议和原始错误。
-   记录任务类型、时间、模型、结果、失败原因、耗时、Token
    数（可获取时）、上下文压缩情况（可获取时）。

## E. Prompt 编辑器、区块与翻译

-   英文 Prompt 是提交 ComfyUI 的实际内容；中文是辅助理解和编辑。
-   支持中英文切换；修改中文后可请求生成英文，修改英文后可重新翻译中文；转换必须审核，不机械一一映射、不自动覆盖。
-   完整文本编辑后由用户手动触发重新翻译，不在每次键入时自动翻译。
-   正向区块建议包括主体人物、外貌服装、动作姿势、场景背景、构图镜头、光影色彩、艺术风格画质；按模型适用性调整，不适用留空或合并，不为填充编造。
-   负向区块独立分类画面缺陷、人体/手脸肢体、构图视角、不希望元素/风格等。
-   区块顺序按模型规则安排；用户可拖动并保存个人偏好，但模型强制顺序优先。
-   区块可启用/停用；停用内容保留但不参与组合。模型强制要求停用时提醒。
-   支持区块预设、完整 Prompt
    模板、自定义区块、区块折叠/拖放和布局记忆。
-   区块可关联架构/模型/Checkpoint；切换模型后重新检查兼容性。状态为兼容、需确认、不兼容，并展示原因。
-   不兼容区块保留内容但默认不参与最终 Prompt。
-   结构化视图和完整文本视图共享同一内容；无法可靠拆分的特殊语法保留原文并提醒，不擅自删除。
-   支持候选差异比较、区块级接受、撤销/重做、语法检查、Token
    长度检查和超长优化候选。
-   Token
    限制按实际文本编码器检查；接近限制提醒，超出警告截断风险；多个编码器分别检查；估算需标明，不自动截断/精简。
-   超长优化提供轻微/适度/重新创作，默认适度；保留意图、锁定内容和重要触发词，结果候选审核。
-   支持复制正向、负向、完整正负向和中英文对照；保留原语法。
-   支持 TXT 和 JSON 导入导出；导入先预览，不覆盖。
-   外部 Prompt
    粘贴/文件导入先作候选；尝试拆分，不能识别时保留完整文本和特殊语法。

## F. 草稿管理（特别重要）

-   多份独立草稿，每个工作流有独立草稿箱。
-   草稿包含正负向
    Prompt、自然语言意图、对话上下文、锁定片段和创建时模型环境快照。
-   模型快照包含工作流标识、Checkpoint 身份/SHA256（已登记时）、实际启用
    LoRA 身份/SHA256/权重、文本编码器、架构等。
-   草稿关联工作流；切换草稿时提醒当前工作流与草稿关联工作流是否一致。
-   支持新建、重命名、切换、删除、复制到其他工作流草稿箱、收藏、标签、备注和搜索。
-   跨工作流复制时保留原始 Prompt
    和模型历史快照，再按目标工作流规则生成适配候选；原草稿不变，不自动写入工作流。
-   **草稿只有用户主动点击保存才持久化。** 编辑、切换工作流、写入
    Prompt、生成图片均不自动保存。
-   有未保存修改时，切换草稿/工作流/正常关闭提示：保存后离开、不保存离开、返回继续。
-   不设临时草稿保护或自动备份；异常退出不保证恢复未保存内容。
-   保存成功后记录重要版本，不是每敲一个字就记录；支持备注、差异比较、恢复。恢复产生新的当前版本，不销毁后续版本。
-   草稿删除需二次确认和回收站；永久删除清理草稿与版本历史，但不影响图片和生成历史。
-   草稿与图片仅建立双向索引；草稿删除不删除生成历史；历史可反向创建新草稿。
-   候选接受、工作流写入和草稿保存互相独立。

## G. LoRA 管理与联动

-   每个 LoRA 独立角色卡与详情页。
-   资料包含预览图/多张示例图、名称、作者、版本、文件名、兼容架构、类型、触发词、推荐权重、作者说明、来源、SHA256、文件路径、使用信息、Prompt
    使用建议。
-   封面可从内嵌元数据、作者/模型页面或用户上传获得；封面和示例图独立存储，不修改
    LoRA 文件。
-   资料来源：文件内嵌元数据、用户导入云端研究结果、用户手动编辑；手动编辑优先，不被自动覆盖。
-   支持多标签、自定义分组、搜索和筛选；标签与分组独立。
-   工作流联动只读展示实际启用 LoRA
    的角色卡、触发词、推荐权重和资料状态；不修改节点或权重。
-   触发词使用智能建议+手动添加；本地 LLM
    可以建议并解释理由，但用户审核后添加。
-   多 LoRA
    协同由程序整理各卡规则，区分人物/服装/画风等；只有实际冲突才提示，不确定不编造。
-   常用 LoRA 组合保存在 LoRA 管理模块，包含成员、权重参考、架构、验证
    Prompt、经验和不推荐搭配。
-   自动匹配当前 LoRA
    组合与常用组合，提示是否参考历史经验，不自动改权重。
-   LoRA
    详情页提供"参与生成的图片"入口，可查看缩略图和完整生成记录；不复制图片。
-   不做 LoRA 使用排行榜、复杂效果统计。
-   新 LoRA
    首次发现可自动登记、读取元数据、提取预览/触发词并创建基础角色卡；缺资料时提示用户。
-   资料完整度：资料完整、部分缺失、待完善；资料缺失不阻断正常生成。
-   文件移动/更名通过 SHA256
    重新定位；找不到时标记暂不可用但保留角色卡和历史。
-   相同 SHA256
    只建一张角色卡，可记录多个文件路径；删除一个副本不影响其他副本。

## H. LLM、显存和任务队列

-   自动读取已安装本地 LLM 模型；用户选择默认模型；不自动下载/安装。
-   支持切换模型；切换不改变
    Prompt/草稿；候选标记所用模型；检查上下文限制。
-   不同草稿上下文隔离；只使用当前草稿、当前工作流/模型规则和实际启用
    LoRA，不读取其他草稿对话。
-   生成前可查看本次参考信息；不要求每次确认。
-   LLM 不可用时暂停需要 LLM
    的功能，不自动调用云端或切换；手动编辑和管理功能仍可用。
-   不同任务参数独立：创作、优化、翻译、摘要；参数包括 Temperature、Top
    P、Repeat Penalty、最大输出 Token；按模型保存个人参数并可恢复默认。
-   术语保护覆盖 LoRA
    触发词、模型关键词、特殊语法、锁定文本和用户指定原样保留内容。
-   **出图前必须卸载 LLM
    并确认进程/模型卸载和显存释放；卸载失败、超时或无法确认时禁止提交。**
-   出图完成后是否自动恢复 LLM 由用户设置；队列仍有待执行任务时不恢复。
-   队列先进先出；支持调整待执行任务顺序；每个任务提交前再次检查 LLM
    已卸载和显存释放。
-   支持连续添加任务、暂停、继续、取消待执行任务；正在执行任务独立管理。
-   生成失败后手动重试，不自动重试；重试保留原始 Prompt、工作流和参数。
-   支持显示排队、准备中、生成中、成功、失败，进度、完成数/待执行数、当前节点和采样步骤（可获取时）。
-   WebSocket 断开自动重连，并通过 HTTP
    状态校准；无法精确获取进度时降级展示状态。
-   成功/失败通知可在切页后看到，声音提醒可开关；支持 Windows
    桌面通知，不用阻断式弹窗。
-   常驻 ComfyUI
    连接状态；自动重连；连接失败禁止新任务；已提交任务断连后重新获取状态，不能直接判失败；最终状态无法确认时标记未知。
-   用户可明确终止当前生成，使用 ComfyUI 支持的中断机制，不杀 ComfyUI
    进程。
-   工作台关闭时不终止已提交任务；未提交队列暂停；重启恢复队列记录；未知状态不自动重出。
-   ComfyUI/电脑/工作台异常退出后恢复历史，未完成任务标记异常中断，不自动重出。
-   多图生成遵循原工作流已有设置；如重复提交多个任务，必须使用同一已审核快照，不得为多图擅自改变
    Batch Size/Seed 等非 Prompt 参数。

## I. ComfyUI 集成与生成历史

-   ComfyUI
    地址和端口可配置，连接测试与自动重连；第一版只管理一个实例，内部保留未来扩展空间。
-   工作流从本地 JSON 导入并登记；未来再支持读取 ComfyUI 当前环境。
-   通过 ComfyUI HTTP + WebSocket API 提交、监听和校准任务状态。
-   ComfyUI
    负责图片生成和原图保存；工作台只记录路径、缩略图索引和历史，不复制/搬动/重新保存原图。
-   输出目录可配置或运行时确认，不永久写死旧路径。
-   历史自动保存六类信息：图片/路径、工作流、正负向
    Prompt、Checkpoint/LoRA、时间、ComfyUI
    任务信息（能获取多少记录多少）。
-   时间轴和图库共用同一历史数据；按日期、工作流、Checkpoint、LoRA、Prompt
    关键词和状态筛选。
-   图片被移动/删除时保留历史并标记文件不存在；用户可手动清理历史，不自动删除历史数据。
-   历史信息可导出，不复制原图。
-   草稿和生成结果的关联是索引，不重复存储；历史记录是当次实际配置快照。

## J. 数据、安全、设置与维护

-   SQLite 保存身份库、规则库、LoRA
    卡、草稿/版本、任务队列、生成历史和设置。
-   数据目录可配置；模型文件和图片原件仍在用户原有目录。
-   手动备份/恢复身份库、规则库、LoRA
    卡、草稿版本、生成历史和设置；恢复前完整性校验。
-   运行日志只记录必要信息和错误；用户可查看错误。
-   诊断报告由用户主动生成，包含版本、ComfyUI/LLM
    状态、GPU/RAM（可获取）、近期错误；默认不上传。
-   默认本地优先；不自动上传，不自动云端 AI；联网功能需用户明确启用。
-   工作台只连接/管理 ComfyUI 任务，不启动/关闭/重启 ComfyUI。
-   中文默认；深浅主题；记住窗口大小、部分布局；支持字体缩放。
-   普通设置导入导出只包含 UI 偏好、LLM
    参数、通知设置，不把模型文件、原图或整个历史数据库混入。
-   手动检查更新，不自动下载覆盖安装；版本变化时提示。
-   功能实用优先，避免复杂模型图、排行榜、Git
    式草稿版本系统、复杂容量/日志/运维平台和重复备份机制。
