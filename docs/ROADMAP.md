# 开发路线图

路线以用户确认的开发顺序为准。UI
可以做足够的功能验证界面，但完整视觉打磨放在后期。

## M0：项目基线与工程准备

目标： - 项目文档、ADR、目录结构和开发规范齐备。 - 建立 React +
TypeScript + Vite 前端与 Python + FastAPI 本机 Web 骨架（同源托管，免安装，见 ADR-0002）。 -
配置格式化、静态检查、测试与本机一键启停入口。

验收： - 本机浏览器访问 `http://127.0.0.1:17890` 能打开工作台页面。 -
FastAPI 同源提供前端产物与 `/api/*`，会话票据 + CSRF 校验生效。 -
停止工作台只结束本工作台进程树，不影响 ComfyUI/Ollama/其他 Python 服务。 -
后端 pytest 与前端 `tsc -b && vite build` 通过。

## M1：ComfyUI 连接与工作流解析

目标： - 配置 ComfyUI URL/端口，连接测试和重连。 - 导入 UI workflow/API
workflow JSON。 - 识别节点、模型、Checkpoint、文本编码器、LoRA 和正负
Prompt 节点。 - 用户确认/覆盖识别结果。 - 保留未知节点和字段。 -
工作流变更检测与重新解析。

验收： - 使用样例工作流建立识别报告。 - 无法确认 Prompt
节点时要求用户指定。 - 未知节点/字段 round-trip 后不丢失。 - 不写入任何
Prompt 以外字段。

## M2：工作流白名单与完整性保护

目标： - 为工作流版本建立 Prompt 白名单。 -
实现深拷贝、快照、结构化差异、白名单写入和回滚。 - 写入后重新验证。 -
识别 UI workflow 与 API workflow 的转换边界。

验收： - 正/负 Prompt 可以写入工作副本。 - 任意非白名单差异都会拒绝。 -
节点增删、连接改变、Seed/尺寸/CFG/Steps/LoRA 变化都会被拦截。 -
写入失败或回滚不确定时禁止提交。

### M1/M2 样本兼容矩阵（真机闭环前必须覆盖）

M1（解析识别，只读）与 M2（白名单写入与完整性保护）在实现上耦合，允许在同一轮迭代交叉交付，但验收分别独立判定。真机闭环前需用真实 ComfyUI 导出样本覆盖以下形态；样本不足的项如实标注 unknown，不标完成：

- 扁平 API prompt（根下直接为 `"1"…"N"` 节点）。
- 带 `nodes` 字典包装的 API prompt。
- UI workflow（仅只读解析，不支持写入）。
- 多文本编码器（正向/负向分别挂载）。
- ConditioningCombine / 自定义中转节点串联的 conditioning 链路。
- 含启用 LoRA 链的工作流；强度为 0 或未启用的 LoRA 不计入生效模型。
- 自定义/未知节点与未知字段：round-trip 后原样保留、不丢失。
- 多图 Batch / 多采样器工作流。

## M3：模型身份库与规则引擎

目标： - SQLite 模型身份、文件路径、SHA256 缓存。 - 架构/模型/Checkpoint
三级规则继承。 - 规则结构、来源、可信度、版本和差异回退。 -
多模型/实际启用 LoRA 规则组合、冲突检测和动态检索。 -
云端研究任务书生成和结构化资料导入审核。

验收： - 同 SHA256 多路径映射同一身份。 - 规则继承优先级由程序确定。 -
冲突和未知信息不由 LLM 猜测。 - 只将当前工作流相关规则传给 LLM。

## M4：本地 LLM 接入与 Prompt 工作区

目标： - Ollama 模型发现、选择、参数配置和任务记录。 -
三种创作模式、候选输出、结构化验证。 -
中英文辅助转换、区块编辑、锁定片段、术语保护。 - 语法检查、Token
长度、复制、导入导出。 - LLM 实时输出、停止、失败诊断。

验收： - LLM 不可用时不自动切云端。 - 输出验证失败时当前 Prompt 不变。 -
候选审核前不写入工作流。 - 当前草稿上下文与其他草稿隔离。

## M5：草稿与版本管理

目标： - 多草稿、每工作流草稿箱、手动保存。 -
草稿模型环境快照、版本差异、恢复、备注。 - 标签、收藏、搜索、回收站。 -
草稿与生成历史双向索引。

验收： - 没有用户主动保存动作就不持久化草稿修改。 -
切换/关闭有未保存提醒。 - 恢复旧版本产生新版本。 -
删除草稿不删除生成历史和图片。

## M6：ComfyUI 队列与显存调度

目标： - Ollama unload、运行状态和 GPU 显存验证。 - LLM 与 ComfyUI
任务互斥。 - 队列先进先出、暂停/恢复/取消/调整/重试。 - ComfyUI HTTP
提交、WebSocket 进度、HTTP 状态校准。 -
断线恢复、异常退出恢复、通知和手动中断。

验收： - 无法确认 LLM 卸载或显存释放时绝不提交。 -
队列有待执行任务时不恢复 LLM。 - WebSocket 短暂断线不直接判失败。 -
unknown/interrupted 任务不自动重出。 - 工作台退出不终止已提交 ComfyUI
任务。

## M7：生成历史

目标： - 自动保存 Prompt/工作流/模型/任务快照。 -
记录图片路径和缩略图索引，不复制原图。 - 时间轴和图库双视图。 -
搜索、筛选、导出和历史反向创建草稿。

验收： - 文件丢失时历史保留并标记不存在。 -
Prompt/模型快照不受后续草稿修改影响。 -
原图仍由 ComfyUI 输出目录管理。

## M8：LoRA 角色卡与组合管理

目标： - LoRA 元数据读取、SHA256 身份、多路径。 -
角色卡、封面/示例图、触发词、作者说明、来源和可信度。 -
标签、分组、资料完整度和个人反馈。 -
工作流只读联动、触发词建议和常用组合。 - 参与生成的图片入口。

验收： - 不自动修改 LoRA 节点、权重或连接。 -
手动资料优先，不被自动覆盖。 - 文件移动后可按身份重新定位。 -
缺失资料不阻止正常生成。

## M9：数据维护与可靠性

目标： - 数据目录配置、备份恢复、数据库迁移。 -
运行日志、用户主动诊断报告。 - 崩溃恢复和数据完整性检查。 -
设置导入导出、手动更新检查。

验收： - 备份覆盖所有约定数据域。 - 恢复前校验完整性。 -
普通设置导出不包含模型文件、原图或整个历史数据库。 -
诊断报告默认不上传。

## M10：UI 全面打磨与免安装交付

目标： - 完成中文优先、深浅主题、布局记忆、字体缩放。 - 打磨 Prompt
工作区、LoRA 卡片、历史图库、队列和设置页面。 - 完善双击启停脚本与本机使用说明；
不产出 EXE/NSIS 安装包（见 ADR-0002）。 - 建立手动检查更新流程。

验收： - 双击启动脚本起服务并打开浏览器，停止脚本按身份回收进程树。 -
交付目录不包含用户的 ComfyUI、模型权重、LoRA 或原图。 - 关键功能在用户
16GB RAM / RTX 4060 Laptop 8GB 环境通过端到端验收。

## 当前下一步

M0 骨架与安全基线已完成。M1 只读解析已用两份真实 UI 格式样本在真机核对通过；
M2 白名单写入闭环已用一份真实导出的 API 格式样本在真机跑通（导入→确认→写入→重开持久化→原始未改→快照校验）。

M3 第一切片已落地（R6）：从 ComfyUI `/object_info` 只读拉取 Checkpoint / CLIP / VAE / LoRA 在册清单，
配置外部目录后做文件名存在性核对，未配置标记为未知；不含 SHA256 身份库与规则引擎。

M3 第二切片已落地（R7）：SQLite 模型身份库骨架，记录路径/大小/mtime/可空 SHA256；目录索引刷新元数据，
大小或 mtime 变化使缓存哈希失效；SHA256 流式按需计算并缓存，大 checkpoint 不 eager 哈希；清单接口回挂身份摘要。

M3 第三切片已落地（R8）：同类别内相同 SHA256 的多副本归并到同一身份组（identity_key + 副本列表）；
无摘要不做哈希推断。

M3 第四切片已落地（R9）：规则记录结构（层级/作用域/键/值/来源/可信度/版本/备注）与纯解析层，
程序确定 checkpoint > architecture > global 继承优先级；同层冲突标记 conflict 不替选，未覆盖字段
unknown 不造默认；只解析请求的键。规则持久化存储、资料导入、多模型/LoRA 组合、冲突人工裁决、
动态检索与 LLM 上下文组装尚未实现。

M3 第五切片已落地（R10）：规则 SQLite 持久化（workbench_rule 表，upsert/查/删，JSON 值往返），
装载为引擎记录做三级继承解析；只读检索接口 `/api/rules` 与 `/api/rules/resolve`，只解析请求键，
冲突/未知如实上报。规则写入/导入接口、旧 profiles 结构化入库、前端规则管理界面尚未实现。

M3 第六切片已落地（R11）：规则 upsert/删除 HTTP 接口，受本地会话与 CSRF 保护；pydantic + 引擎记录双重校验，
非法记录 400 不写库；前端补齐 `apiDelete`。旧 profiles 文本结构化导入、前端规则管理界面尚未实现。

M3 第七切片已落地（R12）：旧 profiles 文本解析器，标注映射来源/可信度，缺失字段记 unknown 不臆测；
候选投影为规则记录形状但不入库。候选→规则库的审核导入流程、前端规则管理界面尚未实现。

M3 第八切片已落地（R13）：旧档案扫描清单与单档案候选预览只读接口；预览不落库，损坏档案容错不抛 500。
候选审核导入规则库、前端档案/规则管理界面尚未实现。

M3 第九切片已落地（R14）：档案候选可整档导入为 checkpoint 级规则，落库前引擎校验，非法候选跳过回报；
导入后可经规则解析回读。

M3 第十切片已落地（R15）：生成参数散文值拆为可比较结构（数值/范围/下限/分辨率列表/采样器列表），
解析失败保留原文不臆测；结构化随规则落库并回读。

M3 第十一切片已落地（R16）：导入按分节分流层级，ARCHITECTURE 节落架构级（scope=底座标签），
其余落 checkpoint 级；无底座标签的架构字段拒绝并回报。global 级规则暂无来源，留后续。

M3 第十二切片已落地（R17）：按工作流识别出的 checkpoint 文件名精确匹配规则库，归集 checkpoint/架构/全局
相关规则形成上下文；未识别或未登记模型返回 unregistered、空规则集，不臆造；不相关规则不进入上下文。

M3 第十三切片已落地（R18）：上下文规则经引擎三级继承解析，装配为可下发的裁剪提示载荷；字段保留来源层级、
来源、可信度与版本；同层冲突标记 conflict、未覆盖标记 unknown，未注册模型空载荷且禁止猜测。

M3 第十四切片已落地（R19）：采样器参数快照入报告；规则结构化值与工作流实际参数保守比对，可判定给
match/out_of_range/out_of_set，不可判定归 unknown，只读不回写。

M3 第十五切片已落地（R20）：架构标签归一化到规范家族，同义变体同家族归并架构规则；混合/派生标签
标 mixed 不并入纯家族；checkpoint 身份指针保留原始标签，未登记模型不猜家族。

M3 第十六切片已落地（R21）：参数值解析前剥离尾部括号备注，清洗副本结构化、raw 保留原值；单值
采样器/调度器归单元素列表；分号两套建议不混并。

M3 第十七切片已落地（R22）：解析层提取 latent 节点宽高，Resolution 规则与实际 latent 尺寸按
整数集合保守匹配；缺尺寸或非数值归 unknown，不臆测匹配。

M3 第十八切片已落地（R23）：Resolution 在原始文本上提取括号内尺寸并去重；数值/列表字段维持
尾部备注剥离口径，两条解析路径互不误伤。

M3 第十九切片已落地（R24）：识别 CLIPSetLastLayer 节点，把负停止层数派生为正数 clip_skip 注入
比对 actuals；非标准值不换算，缺实际值归 unknown。

M3 第二十切片已落地（R25）：多采样器组保守标注——actuals 顶层取首组，sampler_groups 列出各组
参数摘要，组间不合并不替选；逐组比对在后续切片。

M3 第二十一切片已落地（R26）：工作流工作区新增规则与参数比对只读面板，展示注册状态、实际参数
摘要、逐条比对结论与计数；不做勾选驳回或规则写入。

M3 第二十二切片已落地（R27）：多采样器组逐组独立比对，`sampler_group_comparisons` 给出每组
节点、参数、逐条结论与分组计数；前端分组卡片展开，组间不合并不替选，顶层结论仍对应首组。

M3 第二十三切片已落地（R28）：服务与设置页新增规则库只读清单，按三级分组展示规则键、作用域、
值、结构化摘要、来源、可信度与版本；不开放前端写操作。

M3 第二十四切片已落地（R29）：多 latent / 多 CLIP 跳过层节点保守标注。解析段在保留顶层首节点
事实的同时全量列出 `latent_nodes`、`clip_skip_nodes`，actuals 透传节点计数与摘要；前端摘要区提示
结论取首个、其余节点未参与比对；多节点取舍与逐节点比对留后续切片。

M3 第二十五切片已落地（R30）：服务与设置页新增旧档案候选只读预览面板，拉取档案清单并可展开
懒加载单份候选明细（层级、作用域、值、结构化、备注、来源/可信度/版本）；纯只读，不提供导入、
勾选或驳回入口；候选审核写界面留后续切片。

M3 第二十六切片已落地（R31）：抽出前端共享格式化工具，结构化规则值与比对 verdict 提炼值由原始
JSON 改为可读摘要（数值、范围 `a~b`、下限 `≥a`、分辨率列表、采样器列表）；纯展示层，不改后端
解析与比对结论；未知形态回退 JSON。

下一步继续 M3：global 级规则明确来源后装载、
结构化参数的前端展示与比对、逐候选勾选/驳回/差异预览、来源/可信度/版本/差异回退、
多模型与启用 LoRA 规则组合及冲突人工处理界面、云端研究资料导入审核；之后 M4 Ollama 候选生成、
M6 ComfyUI 任务提交与结果拉取。工作流安全边界是全项目最重要的基础。
