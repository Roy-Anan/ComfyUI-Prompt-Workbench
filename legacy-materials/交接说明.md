## 2. 五分钟跑起来

### 2.1 先确认三件事

1. Windows 本机，NVIDIA 显卡，当前目标环境是 8GB 显存（本机 RTX 4060 Laptop）。
2. 秋叶 ComfyUI 整合包在 `D:\AI\Qiuye\ComfyUI-aki-v3.2\`，ComfyUI 服务在 `http://127.0.0.1:8188`。
3. Ollama 桌面版已启动，模型库能看到 `qwen3:latest` 和 `comfyui-prompt:v1`；不要自己另起 `ollama serve`，否则模型库是空的。

工作台自身只用 Python 标准库；唯一指定的解释器是：

```text
D:\AI\Qiuye\ComfyUI-aki-v3.2\python\python.exe
```

如果换机器，改 `启动工作台.bat` 里的 `PYEXE`，或直接用可用的 `python` 启动。

### 2.2 启动顺序

1. 启动 Ollama 桌面版（确认托盘/服务在运行）。
2. 启动秋叶 ComfyUI，确认浏览器能打开 `http://127.0.0.1:8188`。
3. 双击项目根目录的 `启动工作台.bat`；它会执行 `app\server.py`，并在服务绑定成功后自动打开默认浏览器。
4. 如果浏览器没有自动弹出，手动打开 `http://127.0.0.1:8199`。
5. 打开 `http://127.0.0.1:8199/api/health`，应返回 `version: "2.0"`。

只验收工作台本身时，不要求先出图；要验完整链路时，按第 5 节做一次真实出图。

### 2.3 第一次使用

1. 左栏选择 checkpoint（只认 `rules\模型数据库.txt` 登记的完整文件名）。
2. 选择工作流，或先导入 UI / API 工作流。
3. 新建对话，输入你的画面需求。
4. 检查助手返回的正/负提示词与参数；确认后点“生成”。
5. 出图完成后在右栏看图片和出图记录；点图片可放大、下载。

### 2.4 最常见启动问题

| 现象 | 先查什么 |
| --- | --- |
| 8199 打不开 | 是否已有工作台实例占用端口；先停旧实例，不要开两个 |
| 页面能开但对话失败 | Ollama 桌面版是否在跑；`ollama list` 是否有 `comfyui-prompt:v1` |
| 生成按钮报 ComfyUI 连接失败 | 8188 是否在跑；秋叶控制台是否已完全启动 |
| 显存不足 / 出图很慢 | 是否同时挂着 Ollama 和 ComfyUI；看页面顶部显存 chip 与运行条 |
| 出图成功但图片不显示 | 看 `outputs\` 是否落盘，浏览器是否能访问 `/api/generations/.../image/1` |

更完整的故障表在 `部署步骤_Windows.md` 第六节。

## 4. 工程地图

### 4.1 顶层目录

| 路径 | 职责 | 能不能直接改 |
| --- | --- | --- |
| `app\` | 后端：HTTP 服务、Ollama、ComfyUI、规则匹配、历史、显存、日志、备份 | 可以，按 `AGENTS.md` 流程 |
| `web\` | 前端：`index.html`、`style.css`、`app.js` | 可以，改完跑 UI 自检 |
| `tests\` | 单元测试与真机冒烟 | 可以，新增阶段测试按模板 |
| `tools\` | 打包、校验、UI 探针、探针脚本、清理 | 可以，但不要塞运行时代码 |
| `rules\` | 运行时规则：模型数据库、系统提示词、模型索引、输出模板 | 改规则要留依据，不能凭感觉 |
| `profiles\` | 13 个模型的 profile（参数依据、正负提示词约束） | 加模型按 README 步骤 |
| `rules_source\` | 规则包原始资料与 `模型说明.xlsx` | 原则只读；要改先记来源 |
| `history\` | 会话、提示词、出图记录、上下文快照 | 用户数据，不打包，不随意删 |
| `settings\` | 应用设置与上一版备份 | 用户数据，不打包 |
| `outputs\` | 出图原图 | 用户数据，保留；不打包 |
| `workflows\` | 导入的工作流与人工映射 | 用户数据，不打包 |
| `backups\` | 备份 ZIP 与 `_trash` | 用户数据，不打包 |
| `logs\` | 运行日志、测试记录、UI 截图 | 可作为证据，不打包用户数据；打包时只带测试证据 |
| `dist\` | 最终 ZIP | 发布产物，不递归打包 |

### 4.2 后端模块

| 模块 | 主要职责 |
| --- | --- |
| `app\server.py` | HTTP 路由、静态页面、接口编排、启动入口 |
| `app\profile_lookup.py` | 完整 checkpoint 文件名的精确匹配、模型库完整性 |
| `app\prompt_context.py` | 系统提示词 + 当前模型 profile + 对话上下文的注入 |
| `app\prompt_extract.py` | 从助手回复中切出正/负提示词与参数，不改写内容 |
| `app\output_guard.py` | 检测输出跑飞（长度、逗号、重复短语），只判定不改写 |
| `app\ollama_client.py` | Ollama 对话、卸载/预加载、连接桌面版服务 |
| `app\comfy_workflow.py` | 解析 UI / API 工作流，按连线判定正负节点 |
| `app\workflow_lib.py` | 工作流库导入、列出、映射、删除归档 |
| `app\comfy_api.py` | UI Workflow → API Prompt 转换、提交、轮询、取图、`/free` |
| `app\vram_manager.py` | 8GB 显存状态机：卸 Ollama → 出图 → 释放 ComfyUI → 恢复 Ollama |
| `app\history_store.py` | 会话、消息、提示词、出图记录的原子落盘与归档 |
| `app\settings_store.py` | 设置读写、白名单校验、保存前备份 |
| `app\backup.py` | 备份 history/settings/workflows/config，ZIP manifest 带 SHA256，删除进 `_trash` |
| `app\workbench_log.py` | JSON 行日志、滚动、内存最近 600 条、启动读回 |
| `app\runtime_state.py` | 当前任务、计数器、last_error，供运行条使用 |
| `app\lora_meta.py` | 读 safetensors 头部识别 LoRA 架构，不按文件名猜 |

前端只有三个文件：`web\index.html` 管结构，`web\style.css` 管深色样式，`web\app.js` 管交互和接口调用。

## 6. 数据、备份和删除边界

| 数据 | 位置 | 备份 | 打包 | 删除 |
| --- | --- | --- | --- | --- |
| 会话 / 提示词 / 出图记录 | `history\` | 是 | 否 | 删除会话移入 `_archive`，不直接抹除 |
| 设置 | `settings\` | 是 | 否 | 保存前留 `app_settings.bak.json` |
| 工作流与人工映射 | `workflows\` | 是 | 否 | 页面删除归档，不直接抹除 |
| 出图原图 | `outputs\` | 否 | 否 | 用户要求保留，不自动删 |
| 备份 | `backups\` | 不备份自身 | 否 | 删除只移入 `_trash` |
| 运行日志 | `logs\` | 否 | 只带测试证据 | 滚动保留，不自动清空 |
| 程序与配置 | 根目录 | `config.json` 进备份 | 是 | 升级不覆盖用户数据 |

最终 ZIP 明确排除：`history / settings / outputs / backups / dist / __pycache__ / chrome_headless`。

## 8. 已知边界

这些是当前真实边界，不是待办清单；不要为了“看起来完整”而假装已解决：

- 8GB 显存下 Ollama 与 ComfyUI 不能同时驻留；默认 `batch_size=1`。
- 主题只做深色；设置里选浅色会被强制回 `dark`。
- 备份不含 `outputs\` 原图与 `logs\`。
- `confirm_delete` 是页面二次确认；直接调 API 不会弹确认。
- 出图 400 校验失败也会计入 `errors`，并写 `last_error`。
- 同参数同种子可能命中 ComfyUI 执行缓存，1–2 秒返回同图，不代表重新计算。
- 本机没有系统级 Python；依赖秋叶包内解释器。
- `nvidia-smi` 首次直调可能空输出，需要重定向读取；显存管理已处理这个坑。
- 阶段 1 没有单独的 `阶段1_实施记录.md`，其实现记录在 `规则包整合记录.md`，测试证据在 `logs\阶段1_最终验证.txt`。
- 项目是单机 localhost 方案，不提供公网部署、账号体系或多用户隔离。

完整边界见 `README_使用说明.md` 的“V2.0 的边界”和 `阶段7_实施记录.md` 第八节。
