## 2. 注入结构（可直接核对）

`GET /api/context?workflow=suyuexisdxl.json` 返回的 system 实测 **8607 字符**，顺序为：

1. `rules\系统提示词_Ollama精简版.txt` 全文；
2. `【当前模型】` + 架构 / 派系 / 画风 + `【匹配依据】模型数据库.txt 精确匹配 → profiles/IntoRealism_Ultra_V8.txt`；

4. `【当前工作流上下文】`——Checkpoint、LoRA 及强度、采样参数、分辨率、文本节点编号；
5. `【工作台附加约束】` + `【要求】`。

未登记时：`{"ok": false, "reason": "unregistered", ...}`，无 `system` 字段（13 个模型全覆盖测试 + 反例测试已验证）。

### 3.3 真实对话的 4 次实测（含失败，不粉饰）

`tools\chat_demo.py` 固定提示词：*白发少女坐在窗边，午后逆光，半写实插画风，氛围安静*；固定工作流 `suyuexisdxl.json`。

| 轮次 | 参数 | 用时 | 输出 | 结果 |
| --- | --- | --- | --- | --- |
| A | Modelfile 默认（temp 0.7，无输出上限） | 111.3s | 17274 字符 | **失败**：Negative 里 `drawing, painting` 接龙几十次，无停止 |
| B | + repeat_penalty 1.12 / num_predict 1200 | 54.6s | 5419 字符 | **失败**：312 个负面标签（`hp printer artifacts` 式枚举），被 1200 token 截断 |
| C | temp 0.35 / repeat_penalty 1.3 / num_predict 1400 + 工作台附加约束 | 24.3s | 1760 字符 | 基本可用：五段齐全、30 个负面标签、`ClipSkip=[未给出]` 正确；尾部多一条 `已完成` 分隔线 |
| D | 同 C 参数（模型随机性） | 54.0s | 6993 字符 | **失败**：`【模型适配说明】` 变成动词接龙，触发 1207 token 上限 |
| E | D 之后加入失控检测 + 自动重试 | 21.3s（未触发重试） | 1338 字符 | **通过**：六段齐全、25 个负面标签、参数带 `[作者推荐]`、`ClipSkip=未给出`、无多余尾巴 |

结论三条：

1. 注入链路本身没有问题——每次 system 都是 8607 字符、Profile 全文、参数依据都在；模型也认得出当前模型是谁。
2. 这个 8B Q4 量化模型在长负面清单/说明段上**会随机进入接龙**，同样的参数 A~E 里 2 次正常、3 次失控；这是模型能力问题，不是注入问题。
3. 工作台不能靠运气：所以加了下节的检测与重试。

## 4. 工作台附加约束（不属于规则文件）

为压住失控，system 末尾由工作台追加一小块 `【工作台附加约束】`，只约束输出形式，不碰规则内容：

1. 分段标题用系统提示词第 11 节的中文原名；
2. Profile 里写“未给出”的字段就写“未给出”，不许改成“不适用/无需”或凭常识补；
3. 参数必须带依据标记；
4. 写完即停，不追加说明/总结/寒暄/表情/“已完成”标记、不输出分隔线；
5. Negative ≤ 40 个标签，同一标签只出现一次。

`rules\` 和 `profiles\` 下所有规则文件**未改动一个字节**（阶段 1 的哈希校验仍有效）。

| 参数 | 值 | 来源 |

## 6. 失控检测与自动重试（计划书没写，工作台自加）

`app\output_guard.py` 判定失控：篇幅 > 5200 字符、逗号 > 180 个、同一三词短语连续重复 > 3 次，命中任一即判失控。

`POST /api/chat` 命中失控时自动重试一次：在最后一条用户消息后追加简短要求（只六段、Negative ≤ 40、说明 ≤ 3 句、禁止罗列），并用 `temperature 0.2 / repeat_penalty 1.4 / num_predict 900` 重跑；两次都失控就取较短的那份，并在响应里带 `guard.reasons`，页面显示“⚠ 输出可能失控”。

不替模型改写文本、不静默截断当成功——只判定、只重试、只提示。

## 8. 已知问题与欠账（阶段 2 范围外，未假装完成）

1. **模型输出稳定性**：即使加了约束，仍可能偶发接龙（A~E 里 2 次正常 3 次失控）；可靠做法是换更强模型或加结构化输出（阶段 7 UI 完善时再评估）。
2. **英文标题偶发**：C 轮出现过 `【Current Model】` 这类英文标题；E 轮与最终冒烟都是中文标题，但未做到 100% 稳定。
3. **质量标签**：正向里偶发 `(masterpiece), best quality`，与系统提示词“不要机械堆质量标签”相违背；属模型行为，未在工作台层删除。
4. **多轮历史未持久化**：只在内存里保留当前会话最近 20 条，刷新即丢（阶段 3 做）。
5. **正负节点未识别**：`text_nodes` 只给编号与预览，阶段 4 按连线判定。
6. **计划书原有欠账仍在**：`待核实抓取清单.txt` 13 个模型参数缺口未回填；`TEST_FEEDBACK\` 无本机实测。
