# 阶段 3 实施与验收记录

计划书阶段 3 = **多轮对话与历史**（任务 1~6，验收：关掉工作台重启后历史仍在）。本记录写清落地方案、实测结果和没做到的部分。

- 实施日期：2026-11-15
- 版本号：`2.0-stage3`
- 环境：Windows 本机，ComfyUI 秋叶包 Python 3.13.11，Ollama 桌面版 0.40.15（`comfyui-prompt:v1`）

## 1. 计划书要求 → 落地情况

| 计划书要求 | 落地 | 在哪 |
| --- | --- | --- |
| 实现多轮 Ollama 请求 | 服务端读盘取最近 N 条消息（N=设置里的 `history_max_messages`，默认 20）拼进 messages | `app/prompt_context.py` + `server._chat` |
| 自动保存对话 | 每条用户消息、每条助手回复、每次抽出的提示词都落盘；`auto_save_history` 可关 | `app/history_store.py` |
| 支持历史对话切换 | 左栏会话列表，点一条加载整段对话（消息 / 标题 / 工作流一起恢复） | `web/app.js` + `GET /api/conversations/<id>` |
| 支持继续修改提示词 | 多轮上下文天然支持“接着上一轮改”；`重新生成` 用同一条需求重跑 | `POST /api/chat`（含 `regenerate`） |
| 支持复制提示词 | 每条助手回复下 `复制 Positive` / `复制 Negative` / `复制全文` | `web/app.js` |
| 支持恢复上下文 | 上下文由服务端读盘拼装，刷新页面、重开浏览器、重启服务都能续 | `history_for_ollama()` |
| 对话标题管理 | 标题输入框，回车或失焦保存；首句自动当标题（用户改过的不覆盖） | `POST /api/conversations/<id>/rename` |
| 新建 / 删除对话 | `新建` 按钮；删除弹确认，文件移到 `_archive` 不直接抹掉 | `archive()` |
| 对话不能只在浏览器内存 | 全部落 JSON，浏览器只是显示层 | `history\` 目录 |
| 关闭工作台后数据不丢 | 冒烟里真停进程再起，4 条消息与标题原样还在 | `logs\冒烟结果_阶段3.txt` 第 32~34 行 |
| 更换工作流不清聊天历史 | 切工作流只更新会话的 Checkpoint / workflow 字段，消息不动 | `server._chat` 的 `changed` 分支 |
| 删除历史需要确认 | 前端 `confirm()`；服务端只归档 | `web/app.js` |
| 保存配置前备份旧配置 | 每次保存前复制成 `app_settings.bak.json` | `app/settings_store.py` |

## 2. 数据落盘结构

```
history\
  conversations\<c-YYYYMMDD-HHMMSS-xxxx>.json
  prompts\<p-YYYYMMDD-HHMMSS-xxxx>.json
  history_index.json
  conversations\_archive\<id>.deleted-<时间>.json
settings\
  app_settings.json
  app_settings.bak.json
```

对话文件字段（对齐计划书「十三」）：

| 字段 | 说明 |
| --- | --- |
| `conversation_id` | `c-日期-时间-4位随机`，正则校验，`../` 之类进不来 |
| `title` / `created_at` / `updated_at` | 标题与时间戳（带时区） |
| `messages` | `role` / `content` / `at` / `seq`；助手消息另有 `meta`（profile、注入字符、是否重试、token）与 `prompt_id` |
| `checkpoint` / `profile_name` / `workflow_id` | 这段对话用的底模、profile、工作流 |
| `prompt_ids` | 该对话产生的提示词记录 |

提示词记录字段：`prompt_id` / `conversation_id` / `positive` / `negative` / `settings` / `checkpoint` / `profile` / `created_at` / `source_message_seq`。

写入全部走「临时文件 + fsync + `os.replace`」，不会留半截 JSON；索引每次写入自动重建。

## 3. 设置（settings\app_settings.json）

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `application.auto_save_history` | true | 关掉后对话不再落盘（页面会标“未落盘”） |
| `application.confirm_delete` | true | 删除确认（前端固定有确认） |
| `chat.history_max_messages` | 20 | 送进 Ollama 的最近消息条数 |
| `chat.system_prompt_variant` | 精简版 | 精简版 / 全量版，保存后立即生效 |

只接受白名单键，未知键忽略；文件读坏时改名为 `.corrupt-<时间>` 留证再回默认值。

## 6. 与计划书的差异

| 项 | 计划书 | 本次落地 | 原因 |
| --- | --- | --- | --- |
| 存储 | SQLite 或稳定 JSON | JSON（按对话分文件 + 索引） | 数据量小、可直接读、便于备份；计划书允许 JSON |
| 生成记录 / 工作流记录 | 十三节要求一并存 | 本阶段只落了对话与提示词 | 出图、工作流管理分别是阶段 5、4，表结构到时补 |
| 配置 | 一个 config | 地址仍留 `config.json`，运行期设置放 `settings\app_settings.json` | 阶段 1 已有 config，新增项不重复维护 |
| 删除 | 删除 | 归档到 `_archive` | 计划书“不自动删除数据”的要求 |
| 标题 | 可管理 | 首句自动命名，用户改名后不再覆盖 | 减少手填，且不抢用户的命名 |

## 7. 已知问题与欠账

1. **生成记录、工作流记录尚未落盘**：`generation_id` / `comfy_prompt_id` / `image_paths` / `node_mapping` 等字段等阶段 4、5 补。
2. **没有分页与全文搜索**：会话多了列表只是一次性拉 100 条；没有搜索框。
3. **跨进程无锁**：同一目录同时开两个服务进程（例如手滑双击两次 bat）写同一会话可能互相覆盖；单进程内有 `RLock`，多进程未做文件锁。
4. **浏览器交互未实测**：见第 5 节，只做了静态检查。
5. **UI 未提供“编辑某条历史消息后重发”**：当前是“继续多轮”和“重新生成最后一条”，比计划书的“提示词修改”弱一点。
6. **本机 8B 模型输出仍不稳定**：第二轮 2980 字符，偶发接龙会触发自动重试（阶段 2 已有记录）。
