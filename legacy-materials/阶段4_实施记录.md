## 2. 正负节点判定规则（这次的核心）

```
KSampler.positive ──link──▶ 上游节点
                            ├─ CLIPTextEncode → 收文本
                            ├─ ConditioningCombine → 继续往上追（可多个）
                            └─ 其它透传节点 → 继续往上追
KSampler.negative ──link──▶ 同上
```

- 不按“正向=4、负向=5”这类固定编号，也不按节点标题（用户常把标题写反）。
- 找不到采样节点 / 连线上没有文本节点：结果标 `unresolved` 并在 `warnings` 里写明，不猜。
- 有多个采样节点时：取第一个并在 `warnings` 里提示，可用人工映射换。
- UI 与 API 两种格式用同一套语义（API 的 `[节点, 槽位]` 引用同样按图回溯）。

## 5. 过程中修掉的问题

1. **冒烟第一轮失败：第二轮模型跑飞**（6659 字符英文联想接龙，一次重试也没救回来，导致该轮抽不出提示词记录）。
   - 改法：重试从 1 次扩到最多 2 次，参数逐次收紧（0.2/1.4/900 → 0.1/1.5/700），按“未失控优先、其次更短”取结果。
   - 冒烟断言也从“两轮各一条记录”改成“至少一条 + 打印每轮有无”，避免模型随机性伪装成功能回归；本次复跑两轮都抽到了（2 条）。
2. **会话列表排序偶发不稳**：同一秒创建的会话 `updated_at` 相同，排序看扫描顺序。时间戳改成毫秒精度，测试加 20ms 间隔，稳定复现。
3. **节点 ID 类型统一**：阶段 2 里 UI 格式返回整数、API 格式返回字符串，现在统一成字符串（前端与 JSON 都省心），`test_stage2` 相应用例同步更新。
4. **路径穿越从“悄悄 basename”改成直接拒绝**：`../x` 这类输入在 resolve / 映射 / 删除处一律返回失败，不再悄悄转成 `x.json`。
5. **删除工作流时清掉残留映射**，冒烟清理脚本同时修索引里的幽灵条目。
