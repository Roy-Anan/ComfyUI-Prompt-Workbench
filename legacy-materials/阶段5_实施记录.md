## 二、UI Workflow → API Prompt 怎么转

不硬编码节点字段顺序，全部以 ComfyUI `/object_info` 为准（`convert_ui_to_api(ui, object_info)`）：

1. **节点**：遍历 UI 的 `nodes`，节点键保持原 id（字符串），`class_type` 取 `type`，另存 `_meta.title` 便于排错。
2. **输入顺序**：按该节点 `input_order.required` + `input_order.optional` 依次处理，不靠数组猜测。
3. **控件 vs 连线**：类型是 `INT / FLOAT / STRING / BOOLEAN / COMBO`（或下拉数组）就是控件，从 `widgets_values` 取；其余（`MODEL / CLIP / VAE / LATENT / IMAGE / CONDITIONING` …）必须来自连线，输出 `[来源节点id, 槽位]`。
4. **`control_after_generate`**：KSampler 的 `seed` 后面那个 `randomize / fixed / increment / decrement` 是前端占位，不是参数——读到就跳过，所以 `step=35` 不会被写成 `"randomize"`。
5. **Reroute**：遇到 `Reroute` 节点继续往上游追（最多 10 层，防成环）。
6. **PrimitiveNode**：如果控件被转成了输入、来源是 `PrimitiveNode`，直接取它的值写进参数。
7. **静音 / 旁路**：`mode=2`（静音）与 `mode=4`（旁路）节点跳过并给 warning（当前工作流没有这类节点）。
8. **缺节点定义**：抛 `ConversionError`，明确说哪个节点、哪个类型——“自定义节点没装”不静默当成空节点。
9. **`widgets_values` 为字典**：新版前端可能按名字存，按 name 取。
10. **未连线的纯连线输入**：不写，交给 ComfyUI 用默认/报错，避免瞎填。

实测（`logs\convert_probe.txt`）：`suyuexisdxl.json` 8 个节点全部转换成功、warnings 空；KSampler 得到 seed 231661496131269 / 35 步 / CFG 5.5 / dpmpp_2m_sde / karras / denoise 1，模型连 `10`、正 `4`、负 `5`、latent `6`，与阶段 4 解析结果逐项一致；`set_text_inputs` 与 `apply_overrides(seed=1234)` 都生效。

## 三、提交、轮询、取图

`ComfyClient`（只连本机 `http://127.0.0.1:8188`）：

- `object_info()` 缓存 10 分钟，避免每次出图都拉 1444 个节点定义。
- `queue_prompt()` POST `/prompt`，带 `client_id`；HTTP 400 时解析 `error` + `node_errors` 原样带回；连不上单独给“连不上 ComfyUI”这类可重试错误。
- `wait(prompt_id)` 每秒查 `/history/{prompt_id}`；`status.completed` 为 true 取结果，`status_str=error` 从 `messages` 里抽 `exception_message` / 节点号 / 节点类型；默认 300 秒超时（`config.json → comfyui.timeout`）。
- `images_from_history()` 扫各节点 `outputs.images`，拿到 `filename / subfolder / type`。
- `save_images()` 逐张 GET `/view?...`，存到 `outputs\<generation_id>\01.png`，记录字节数；下载失败保留条目和错误，不让整次出图失败。

一个要说明的现象：**同一组提示词 + 同一个 seed 再提交，ComfyUI 会命中执行缓存，1–2 秒就返回同一张图**（`prompt_id` 是新的，文件名不变，不重新计数）。所以本次既看到 1.4 秒的缓存命中，也看到 56.8 / 66.7 秒的真实计算，二者都不是假出图。

## 四、生成记录怎么存

目录：`history\generations\g-YYYYMMDD-HHMMSS-xxxx.json`（正则 `^g-\d{8}-\d{6}-[0-9a-f]{4}$`，拒绝路径穿越）。

字段：

```
generation_id / conversation_id / workflow / checkpoint / profile
positive / negative / params{sampler,latent,text} / warnings / workflow_format
prompt_id（ComfyUI 的） / status(running|done|error) / error / attempts
duration_sec / images[{filename,subfolder,type,local,bytes}] / retry_of / retried_by
created_at / updated_at
```

- 每次出图先落一条 `running`，完成后原地改 `done`（失败改 `error`），断电最多留一条 running。
- 挂在对话上：`conversations\<id>.json` 的 `generation_ids` 追加；列表 `/api/generations?conversation_id=` 从文件扫，不依赖浏览器内存。
- 同时把这次真正提交的 API Prompt 存成 `outputs\<gid>\prompt.json`（含正负提示词），以后能逐字段复现或排查。
- 对外返回一律换成 `/api/generations/<gid>/image/<n>`，不暴露 `D:\` 绝对路径（单测与冒烟都校验）。

## 五、失败与重试

- **提交阶段**：连接类失败自动再试 1 次（间隔 1.5 秒）；节点校验失败不重试，直接把 `node_errors` 带回前端。
- **执行阶段**：超时 / `execution_error` / 没有图片输出，都落 `status=error` + 原因，前端卡片显示错误并提供“重试”。
- **`POST /api/generations/<gid>/retry`**：按记录里的 workflow / 正负提示词 / seed / 步数 / CFG / 尺寸重放，生成一条**新记录**，`retry_of` 指旧 id，旧记录写 `retried_by`。
- 前端“已完成”的卡片给的是“再画一张（新种子）”，会带 `randomize:true` 换 seed，避免又命中缓存出同一张。
- 失败路径实测：不存在的工作流 → HTTP 400 `no_workflow`；不存在的记录重试 → 404。

## 十、已知限制（没做或没测的，照实说）

1. **显存自动切换还没做（阶段 6）**。现在 Ollama 与 ComfyUI 同时驻留时，8GB 卡可能吃紧；冒烟是先卸载 Ollama 再出图。界面上没有“先卸 Ollama 再出图”的自动流程。
2. **真跑只覆盖 832×1216 / 35 步 / batch 1**（8GB 显存的默认档）。其它尺寸、步数、CFG、batch>1 只有单测覆盖参数写入，没有逐组真出图（每次约 1 分钟，未做穷举）。
3. **重试同参数会命中 ComfyUI 缓存**：接口、记录、状态都验证了，但那一次不是重新计算；要真重算得换 seed（“再画一张”走的就是这条）。
4. **失败重试只覆盖“提交失败再试 1 次”与手动重试**；没有指数退避、没有排队超时后的自动续跑。
5. **ComfyUI 断连场景没有真断**（会打断用户正在跑的任务），只验证了“不存在的工作流 / 不存在的记录”这类错误返回。
6. **界面交互没有真人点击验证**：无头截图证明页面渲染与数据联动，但“点出图按钮”这一步由用户实际操作确认；按钮、接口、卡片是三段独立的已验证部件。
7. 没有做旧图清理、缩略图压缩、EXIF/工作流元数据写入 PNG 之外的处理；`prompt.json` 是唯一的复现快照。
8. 当前只允许一次出一张（前端 `genBusy` 串行）；连点会提示“上一张还在出”。
