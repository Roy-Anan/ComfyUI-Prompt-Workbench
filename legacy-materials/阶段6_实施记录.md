要求：启动 Ollama → 生成提示词 → 保存上下文 → 卸载 Ollama → ComfyUI 出图 → 释放显存 → 恢复 Ollama → 恢复对话。

| --- | --- | --- |
| 启动 Ollama | 桌面版服务在跑 0.40.15，模型已注册 | `/api/version`、`/api/tags`；冒烟第 1 行 `Ollama running=True model_registered=True` |

| 卸载 Ollama | 自动 `keep_alive=0`，轮询到空 | `ollama_unload ... 5783 MB → 无`；`/api/ps` 为空 |
| ComfyUI 出图 | 真提交、真计算、真下载 | `g-20261115-220946-4a43`，`prompt_id 5e8a…`，60.9 秒，`pony_sdxl_00160_.png` 1,560,812 字节 |

**结论：链路是实际跑出来的，不是接口模拟。** 冒烟里没有提前手动卸载 Ollama——出图前 `/api/vram` 明确显示 `comfyui-prompt:v1` 驻留，卸载是 `_generate` 自己做的。

## 三、状态机与配置

`app/vram_manager.py`：

- `gpu_memory()`：nvidia-smi 解析；返回 `ok / name / total_mb / used_mb / free_mb / *_gb`，失败带 `error`。
- `VramSession.start(conv_id, auto)`：`ollama_detect → context_snapshot → ollama_unload → gpu_check → comfy_check`。
- `after_comfy()`：`comfy_free`，前后各读一次显存。
- `restore()`：`ollama_reload → context_restore → gpu_after`。
- `abort(reason)`：`abort → rollback_reload`（只回滚原本在显存里的模型）。
- `summary()`：`auto / fatal / finished / steps / ollama_loaded_before / ollama_reloaded / context_snapshot / context_restored / vram_before / vram_after / warnings / errors / total_sec`。

`config.json → vram`：`auto_manage=true`、`min_free_mb=4000`、`wait_free_seconds=40`、`poll_interval=1.0`、`free_comfy_after=true`、`free_wait_seconds=20`、`unload_wait_seconds=20`、`reload_ollama=true`、`reload_wait_seconds=15`、`reload_keep_alive=30m`、`strict_vram=false`。

设计取舍：

- **不硬编码 8GB**：阈值来自配置，换卡只改 `min_free_mb`；读不到 nvidia-smi 只警告，不假装知道。
- **不阻塞出图**：`strict_vram=false` 时空闲不够只警告；需要“宁可不画也不 OOM”就把 `strict_vram` 改 `true`。
- **Ollama 没开不拦出图**：检测失败记 `ollama_skip`，继续出图；只是这次没法“恢复对话”。
- **上下文快照存全量消息**：不截断，便于核对；代价是文件随对话变长。

## 四、服务端与前端

服务端（`app/server.py`）：

- `_generate()` 外加 `GENERATION_LOCK`（非阻塞）：第二张直接返回 `reason=busy`；`_generate_impl()` 保留原逻辑。
- 记录创建后立刻 `VRAM.start()`；`fatal` 时回滚 + `generation.status=error`；提交/执行/无图失败都 `abort` 并写 `vram`；成功则 `after_comfy → restore`，`vram` 一起写进 generation 记录与响应。
- 生成记录新增 `vram` 字段（九步时间线、前后显存、快照路径、恢复标记、warning/error）。
- `/api/status` 增加 `vram`（`auto_manage / min_free_mb / gpu / ollama_loaded / last`）。
- 新增 `GET /api/vram`：配置 + 当前 GPU + 驻留模型 + 最近一次会话。
- `vram_safe()`：显存步骤异常只记 `*_error` 步与错误，不让已经成功的出图变成 500。

## 七、明确没做到 / 有边界的

1. **只真跑 832×1216 / 35 步 / batch 1**：其他尺寸与 batch 只有单测，没有逐档真出图。
2. **显存阈值是经验值**：`min_free_mb=4000` 只是“尽量别 OOM”，WDDM 允许共享内存超额，不能保证 100% 不爆；要硬保证得开 `strict_vram` 并把阈值调高。
3. **`/free` 只能从显存读数判断释放**：ComfyUI 没有查询“已加载模型列表”的公开接口，无法直接确认它内部是否清空，只以显存下降为准。
4. **Ollama 服务本身不代启**：只检测；服务没开就 `ollama_skip`，不会帮你打开桌面 App。
5. **出图超时 / 执行失败时 ComfyUI 队列可能还在跑**：`abort` 只恢复 Ollama，没有 `/interrupt` 取消队列；下次出图前队列若没空，可能排队。
6. **并发只挡出图**：`GENERATION_LOCK` 只保证同一时刻一张图；如果另一个标签页在出图时发 `/api/chat`，Ollama 可能被重新装回显存，和 ComfyUI 抢 8GB。前端是串行按钮，但接口层没锁聊天。
7. **上下文快照不清理**：每次出图一份全文，长期会涨；没有自动保留策略。
8. **第 3 轮正文出现词表堆叠**：冒烟第 3 轮返回 5,022 字符，含重复词表；阶段 2 的失控阈值是 >5,200 字符 / 逗号 >180 / 三词连续重复 >3，这次刚好卡在阈值下没触发。**显存链路与续聊功能通过，但模型输出质量属于阶段 2 的已知边界**；最终排错时应补一条“重复词表 / 无标点碎片”的检测。
9. **界面没有真人点击**：无头 Chrome 截图证明渲染与数据联动，但没有真人完整点一遍“出图 → 刷新 → 再画”。
10. **没有旧图 / 旧快照清理**：阶段 7 的备份与清理一起做。
11. **Ollama 与 ComfyUI 同时驻留仍会爆显存**：这不是本阶段能“优化”掉的，8GB 卡上只能串行；工作台的做法就是卸载 / 恢复。
