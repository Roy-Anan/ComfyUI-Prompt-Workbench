## 二、后端新增与改动

### 2.1 新增模块

`app/workbench_log.py`

- 行格式：`{ts, level, scope, message, fields}`，UTF-8，`ensure_ascii=False`；
- 级别 `debug / info / warn / error`；`recent(limit, level)` 新的在前；
- 滚动：超过 `max_bytes` 后 `workbench.log.1/.2/.3`；
- 启动时把文件末尾读回内存 deque，重启后页面不会只剩“工作台启动”一条；
- `details()` 返回路径、文件列表、大小、滚动份数（**注意不是 `info()`**：`info(scope, message)` 是写日志方法，阶段 7 单测发现同名覆盖后拆开）；
- 不记录提示词正文与对话正文，只记操作、结果、路径摘要。

`app/runtime_state.py`

- `begin(kind, **info)` / `update(kind, stage, **info)` / `end(kind, outcome, error, **info)` / `mark_error` / `snapshot`；
- `snapshot` 含 `started_at / uptime_sec / busy / active / last / counters / last_error`；
- `end` 写 `outcome / error / finished_at / elapsed_sec`；非 `ok` 增加 errors 计数；
- 由 `app/server.py` 的对话、出图、校验失败、异常统一调用。

`app/backup.py`

- 收集 `history/`、`settings/`、`workflows/`、`config.json`；
- 排除 `outputs / logs / backups / dist / __pycache__ / .git / chrome_headless / _trash` 与 `*.tmp`；
- 备份名 `backup-YYYYMMDD-HHMMSS.zip`，同秒冲突加 `-2`；
- `manifest.json` 记录版本、创建时间、备注、分类计数、每个文件的 `path / bytes / sha256`；
- `list()` 读取 manifest 并用 `zipfile.testzip()` 做 CRC；
- `delete()` 移到 `backups\_trash`，不直接删除。

### 2.2 改动模块

`app/settings_store.py`

- 增加 `CHAT_VARIANTS = ("精简版", "全量版")` 与 `validate_patch()`；
- 白名单只认 `application / chat / ollama / comfyui` 下已知键；
- 布尔严格 `true/false`；`history_max_messages` 夹到 2–60；`system_prompt_variant` 枚举；`theme` 强制 `dark`；`base_url` 必须 `http(s)`；
- `save()` 仍返回完整 dict（不破坏旧调用），警告写入 `self.last_warnings`；
- `info()` 增加 `dir`。

`app/server.py`

- 全局 `LOGGER / BACKUPS / RUNTIME`；
- `_send()` 对 4xx/5xx 和 POST 写 http 日志；
- `/favicon.ico` 返回 204，避免浏览器自动请求留下无意义 404 警告；
- 设置页 `system` 信息：版本、服务地址、目录、显存配置、history 统计、备份、日志、规则包体检；
- 生成流程按阶段 `RUNTIME.update`：显存准备 → 提交 ComfyUI → 等待执行 → 下载图片 → 恢复显存与上下文 → 完成；
- 生成校验失败（400/500）统一 `log_event` + `RUNTIME.mark_error`，运行条和日志都能看到原因；
- 对话流程 `RUNTIME.begin`、自动重试阶段、成功 / 失败 `end`；
- `auto_restore_ollama` 设置即时写入 `VRAM.cfg["reload_ollama"]`，关闭后出图收尾不预加载 Ollama。

### 2.3 新增接口

| 接口 | 作用 |
| --- | --- |
| `GET /api/runtime` | 运行状态快照 + 最近 5 条日志 + 最近显存摘要 |
| `GET /api/logs?limit=&level=` | 日志条目 + 日志文件信息 |
| `GET /api/logs/download` | 下载 `workbench.log.txt` |
| `GET /api/backups` | 备份列表 + 数量 / 占用 |
| `POST /api/backups {"note":...}` | 立即备份 |
| `GET /api/backups/<name>/download` | 下载备份 ZIP |
| `POST /api/backups/<name>/delete` | 移到 `_trash` |
| `POST /api/client-log` | 前端错误上报 |

`GET /api/settings` 增加 `system`；`POST /api/settings` 返回 `warnings`。

## 六、日志的 UTF-8 结论

阶段 7 开始时用 PowerShell `Invoke-WebRequest` 发中文 `client-log`，`logs\workbench.log` 里显示成 `??????`。本轮做了两件事：

1. 用 Python `urllib.request` 以 UTF-8 JSON 重发同一接口，日志内容“阶段7 中文日志 UTF-8 校验”原样写入，冒烟项“中文日志不乱码”通过；
2. 文件按 UTF-8 写、按 UTF-8 读；`WorkbenchLog` 启动时 `open(..., encoding="utf-8", errors="replace")` 读回末尾。

结论：`??????` 来自 PowerShell 请求体编码，不是服务端解码或文件写入；浏览器 / Python 客户端不会复现。`workbench.log` 里遗留的一条旧 `??????` 只是历史测试痕迹，不影响当前日志面板与下载。

## 八、边界与没做的事（照实记录）

0. **打包前补修了一个断连堆栈**：浏览器关页面 / 刷新时，`_send()` 的 `wfile.write` 曾抛 `ConnectionAbortedError` 并打印到 `server_stage7_dev_err.txt`；已在 `_send()` 捕获 `BrokenPipeError / ConnectionResetError / ConnectionAbortedError`，断连不再产生 stderr 堆栈（2026-11-15 打包前复跑单测 129/129 通过）。
1. **主题只有深色**：计划书只要求“完善深色 UI”，没有实现浅色主题；设置里的浅色会被强制回 dark。2. **备份不含出图原图**：`outputs\` 不进备份，工作台自己的出图副本不会被备份；ComfyUI 原 `output\` 仍在。需要连图一起备份时，应手动复制 `outputs\`。
3. **备份不含日志**：排错日志不进用户备份，避免把测试痕迹和路径带进用户资产。
4. **日志只保留最近 600 条在内存**：更早的要从 `workbench.log` 文件或滚动文件看；页面“下载日志”导出最近 600 条文本。
5. **`ui_probe.py` 是开发机测试工具**：依赖 `websocket-client`，发布包不把它当运行时依赖；`tools/check_ui.py` 仍是不依赖浏览器的静态自检。
6. **`confirm_delete` 只在页面生效**：直接调 `/api/conversations/<id>/delete` 或备份删除接口不会弹二次确认；本机单人使用，未加服务端确认令牌。
7. **错误计数包含 400 校验失败**：出图参数 / 工作流不存在这类客户端错误也计入 `counters.errors`，便于运行条显示“出过错”；如果只想统计服务端故障，需要另加分类。
8. **未清空 `history\` / `outputs\`**：阶段 6 验收会话与出图仍保留，供 UI 截图和回溯；没有按用户未确认的操作删除测试数据。
9. **UI 截图使用阶段 6 的出图**：预览截图来自 `g-20261115-222040-77bd`（衣着完整的窗边少女），不是重新生成的新图；阶段 7 的冒烟新图 `g-20261115-230315-25b3` 已落盘但未作为截图素材。
10. **端到端只在当前这台 8GB RTX 4060 Laptop 上跑过**：其他显卡 / 其他 ComfyUI 版本的兼容性没有实测。
